# 盤見積アシスタント（デモ版 v1.0・藍彩エディション）

制御盤の仕様書（PDF / Word / Excel）を取り込み、見積に必要な情報の抽出・資料間の照合・盤への収容判定・見積計算・Excel 見積書の作成までを、**出典と根拠を確認しながら**進めるための業務支援システムのデモ版です。

- **ルール抽出 × AI 読解の二重チェック**：辞書・ルールによる抽出と、OpenAI による読解を資料ごとに突き合わせます
- **AI の作り話を見積に入れない**：AI が返した値は、引用が原文に実在し数値が一致するかをプログラムで照合し、確認できない値は採用しません
- すべての値に「どの資料の・どこに書いてあったか」を紐づけ、原文上でハイライトします
- 判断が必要な箇所（矛盾・記載なし・AI だけが読んだ値）は「要確認」として担当者に返し、最終判断は人が行います

## 起動方法

### 1. OpenAI API キーの設定（AI 機能を使う場合）
`.env.example` を `.env` という名前でコピーし、`OPENAI_API_KEY` を設定します。
キーはサーバー側だけで使われ、画面やブラウザには送られません。`.env` は共有しないでください。
キーがない場合も、ルール抽出のみで全機能（AI 機能を除く）が動作します。

### 2. 起動
- **Windows**：[Python 3.11 以上](https://www.python.org/downloads/) をインストールし、`start.bat` をダブルクリック
- **macOS / Linux**：`./start.sh`（`--port 8080 --no-browser` なども指定可）

ブラウザで `http://127.0.0.1:8000` が開きます。`frontend/dist`（ビルド済み画面）が同梱されていれば Node.js は不要です。

### 任意：見積書の PDF プレビュー
[LibreOffice](https://ja.libreoffice.org/) がインストールされていると、出力画面で見積書を PDF 化してプレビューします。

## Docker で起動（PostgreSQL・推奨）

データベース（PostgreSQL）・API（FastAPI + Prisma）・画面（nginx）を Docker Compose でまとめて起動します。

```bash
cp .env.example .env          # OPENAI_API_KEY を設定（AI を使わない場合は空のままで可）
docker compose up -d --build  # 初回はイメージ作成に数分かかります
```

ブラウザで `http://localhost:8088` を開きます（ポートは `.env` の `APP_PORT` で変更）。

| コンテナ | 役割 |
|---|---|
| `db` | PostgreSQL 16。データは `pgdata` ボリュームに保存。開発・テスト用に `127.0.0.1:5434` で接続可 |
| `backend` | FastAPI + Prisma Client Python。起動時に `prisma migrate deploy` でテーブルを最新化。取り込んだ資料・出力した Excel は `files` ボリュームに保存 |
| `frontend` | ビルド済みの画面を nginx で配信し、`/api` を backend に転送 |

よく使う操作：

```bash
docker compose logs -f backend                                   # API のログ
docker compose exec db pg_dump -U panel panel > backup.sql       # バックアップ
docker compose down                                              # 停止（データは残る）
docker compose down -v                                           # 停止してデータも削除
# 以前の JSON 保存の案件をデータベースへ取り込む（元ファイルは変更しない・二度実行しても重複しない）
docker compose run --rm -v "$PWD/backend/data/projects:/import:ro" backend python -m app.import_json /import
```

### データベースの構成（`backend/prisma/schema.prisma`）

| テーブル | 内容 |
|---|---|
| `projects` | 見積案件。更新番号 `rev` による楽観的排他制御（他の担当者が先に保存していれば 409 で知らせ、上書きしない） |
| `documents` | 取り込んだ資料のメタデータ（ファイル本体はボリューム） |
| `parsed_documents` / `ai_results` | 資料の構造化結果、AI 読解・AI-OCR の結果（キャッシュキー付き） |
| `history` | 操作・変更履歴（追記のみ） |
| `revisions` | 承認された見積の版 |
| `master_versions` | マスタ・判定ルールの版（保存のたびに記録。以前の版に戻せる） |
| `users` / `master_data` | 担当者と権限、部品・筐体・判定ルール・変換辞書・AI 設定（初回に `backend/data/master` の JSON から投入） |

スキーマを変更したら `cd backend && prisma migrate dev --name <変更内容>` でマイグレーションを作成します（コンテナ起動時に自動で適用）。

`DATABASE_URL` を設定しない場合（`start.bat` / `start.sh` での起動）は、従来どおり `backend/data/projects` に JSON ファイルで保存します。Docker を使えない PC でのデモ用です。

## デモの流れ（約18分）

1. **「デモ案件で体験する」**：架空の主仕様書（PDF）・変更連絡書（Word）・スキャン図面を登録し、AI が資料を読み解く演出とともに解析（約15秒）。スキャン図面は AI-OCR で寸法注記を読み、変更連絡前の旧版図面（奥行 D600）であることを検出
2. **抽出・確認**：原文ハイライト付きで結果を確認。「ルール×AI 一致」の表示、60Hz／50Hz の矛盾、保護等級の記載なし、変更連絡の反映、表記揺れ補正
3. **AI に質問**：「主回路電源の周波数は結局どちらが正しい？」→ 根拠の箇所をハイライトして回答
4. **顧客回答メールを追加**（ワンクリック）→ 再解析：文章だけのメールから AI が「保護等級 IP4X」「50Hz は誤記」を読み取る
5. **収容判定**：判子で「不可」→ 機器が段に落ちてくる配置図ではみ出しを確認 → **AI 設計レビュー**（主幹 MCCB の容量不足などを指摘）→ W900 筐体で「可」
6. **見積**：原価構成グラフ、利益率スライダー、単価未登録・期限切れの検出
7. **出力・承認**：設計担当が**承認を依頼** → 設計課長に切り替えて承認（判子と桜吹雪）→ 既存 Excel 雛形への転記・質疑書・根拠書 → **AI が送付メールを作成**
8. **見積の版と比較**：承認のたびに「第N版」を記録し、版どうしの金額・明細・仕様の違いを表示
9. **類似過去案件**：見積画面で、仕様・構成機器・インバータ容量・盤サイズが近い過去案件を類似度と「一致した点・異なる点」付きで表示し、今回の金額が類似案件の範囲のどこにあるかを示す。収容判定画面には類似案件の最終盤サイズ（例：同じ構成で W800→W900 に変更した実績）
10. **ルール変更の影響確認**：設計課長が鋼材指数・為替（市況係数）を変更 →「影響を確認して保存」で全案件を再解析し、金額・判定が変わる案件を保存前に表示（承認済みの見積は自動で変えない）。マスタは版として記録され、以前の版に戻せる
11. **精度・効果レポート**：抽出精度、作業時間の削減効果（導入前の想定時間との比較）、収容判定と設計者の最終判断の一致率、全案件の回帰チェック

詳しい進め方と想定問答は [docs/デモ進行ガイド.md](docs/デモ進行ガイド.md) を参照してください。

## AI 機能（OpenAI）

| 機能 | 使用モデル（既定） | 内容 |
|---|---|---|
| AI 読解 | gpt-5.4-mini | 資料を「[ID] 本文」の形で渡し、項目・機器・訂正事項を原文どおり・根拠付きで抽出。項目名が本文にあるのに抽出されなかった項目は再確認 |
| 仕様書に質問 | gpt-5.4-mini | 登録資料だけを根拠に回答。引用は原文と照合し、確認できない引用は表示しない |
| AI 設計レビュー | gpt-5.5 | 容量・保護協調・放熱・配置・見積漏れの観点で指摘（参考所見として表示） |
| 送付メール作成 | gpt-5.4-mini | 見積提出・質疑確認のメールを、解析結果の金額・番号・前提条件を使ってビジネス敬語で作成 |
| AI-OCR | gpt-5.4-mini（画像入力） | テキスト層のない PDF（スキャン図面）をページ画像として読み、文字と寸法注記（W/H/D）・図番・尺度を取得。寸法は書き起こした文字列に実在し数値が一致するものだけを採用し、仕様（変更連絡反映後）と照合 |

**AI の結果の扱い（安全策）**
- 引用が原文に実在し、値の数値が原文と一致しない値は採用しない（件数は解析結果に表示）
- ルールと AI が一致 → 「ルール×AI 一致」。AI だけが読んだ値 → 「要確認」
- AI だけの読み取りがルール抽出と食い違う場合は、承認を止める「矛盾」にはせず参考値として表示
- AI が検出した追加機器は「候補」とし、担当者が確定するまで収容判定・見積に含めない
- 読解結果は資料・モデル・プロンプト版ごとにキャッシュし、再解析で何度も課金しない
- モデルの変更・AI の無効化は「マスタ・設定 → AI 設定」から行えます

### デモ版で簡略化している点

| 項目 | デモ版 | 本番での想定 |
|---|---|---|
| OCR | AI-OCR（OpenAI の画像入力）で図面の文字・寸法注記を読取 | 手書き・細かな文字を含む実図面で精度を検証し、必要に応じて専用 OCR（Azure Document Intelligence 等）と併用 |
| 収容判定 | 段配置の簡易モデル | クライアントの設計基準をルール化し、設計者判断との一致率を検証 |
| データ保存 | PostgreSQL（Docker）。Docker なしの起動時は JSON ファイル | 冗長化・定期バックアップ・保存期間の運用ルール |
| 認証・権限 | 画面で選んだ担当者の役割で権限を判定（`backend/data/master/users.json`） | 社内 AD / Entra ID 連携、案件ごとの閲覧権限 |
| 同時利用 | 更新番号（DB の楽観的排他制御）で他の担当者の更新の上書きを防止。画面にも他の担当者の更新を通知 | 負荷試験（20〜30名）で処理数・応答時間を確認 |
| マスタ | 架空データ（約25品目） | 既存の部品表・購買データから移行 |
| 過去案件 | 架空の受注・失注実績 12 件（`past_projects.json`）＋本システムで承認した見積 | 既存の見積書・受注実績から仕様・構成機器・盤サイズ・金額を移行し、類似度の重みを実績で調整 |
| 効果測定 | 作業時間は操作履歴の時刻から推定（20 分以上の空きは除外）。導入前の時間は設定値 | 導入前の作業時間を実測し、同じ案件で比較 |
| 他システム連携 | CSV（BOM 付き UTF-8） | 連携先（販売管理・ERP・購買）の取込形式・API に合わせて調整 |

```
docker/                    nginx 設定・API 起動スクリプト・テスト用 DB の作成
docker-compose.yml         db / backend / frontend の構成
backend/data/master/       部品・筐体マスタ、判定/算定ルール（市況係数・効果測定の基準を含む）、変換辞書、AI 設定、担当者、過去案件（DB 利用時は初回に投入）
backend/data/templates/    Excel 見積書雛形とセル対応表（cellmap.json）
frontend/                  画面（React + TypeScript + framer-motion、pdf.js で原文表示）
samples/                   デモ用の架空資料（顧客回答メールを含む）
tests/                     自動テスト
```

## 開発

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
(cd backend && ../.venv/bin/prisma generate)                              # Prisma クライアントの生成（初回・スキーマ変更時）
docker compose up -d db                                                   # データベースだけ起動する場合
(cd backend && DATABASE_URL=postgresql://panel:panel@127.0.0.1:5434/panel ../.venv/bin/prisma migrate deploy)
(cd backend && DATABASE_URL=postgresql://panel:panel@127.0.0.1:5434/panel ../.venv/bin/uvicorn app.main:app --reload --port 8000)   # API
(cd frontend && npm install && npm run dev)                               # 画面（http://localhost:5173）
python scripts/make_samples.py     # デモ資料の再生成（LibreOffice が必要）
python scripts/make_template.py    # Excel 雛形の再生成
```
